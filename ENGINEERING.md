# Engineering

How B-Blo builds. This is the development cycle, stated plainly so
anyone, engineer or not, can see how the work gets done.

## The cycle

Every piece of work moves through four stages, in order, as many times
as it takes:

**Study.** Before building, learn what great sounds like. Study the
masters of the form, name what makes them great, and write it down.
Inspiration is fuel; imitation is failure. The studies are part of the
record.

**Build.** Compose in code. Small, reviewable pieces. Every build
records its parameters, seeds, and render commands so the result is
repeatable.

**Ear.** A human judges. Bayo's ear is the final authority on every
track: what stays, what goes, what gets refined. No track ships without
passing it. This is the step most AI-generated work skips, and it is the
step that makes the work real.

**Refine.** Apply the judgment. Version the result. Repeat the cycle
until the work meets the bar.

Study, build, ear, refine. Then again.

## The bar

Two references, in order:

1. **Yeezy.** Radical subtraction. One unmistakable creative authority.
   When in doubt between adding and removing, remove.
2. **Apple.** Restraint as branding. No typos, no placeholders, no
   unresolved inconsistencies. Craft in the details nobody sees.

A track earns release when it would stand beside the best human work in
its form and not apologize.

## Show your work

Build in public, from day one. Source code beside the artifact. Build
notes that say what changed and why. Version history as lab notebook.
The audience sees the work, not just the result, because the work is
part of the result.

## What "done" means

A track is done when all of these are true:

- Bayo's ear approved the current version.
- The source that rendered it is in `source/`.
- The render is reproducible from the recorded parameters.
- The build notes record what changed across versions and why.
- The project's README describes the track accurately.

If any one is missing, the track is still in the cycle.
